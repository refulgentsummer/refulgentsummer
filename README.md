## How I work

The agents write the code. I own the judgment: what the product is for, what the model may never do, whether the result is any good.

- **Wisdom first.** Every build starts from what traditions already know about the thing, then asks what machinery would let it happen for one person at the right time.
- **Prompts as liturgy.** System prompts are design documents: what to listen for, what never to presume, when to ask one question and stop. Every ruling is logged, so a prompt has a history the way a rite does.
- **Rubric vs. constraint.** Prompt instructions set intent; code enforces what may never occur. Most failures I've seen come from using one where the other belonged.
- **Discernment as evaluation.** Harnesses replay hundreds of real records and adjudicate every disagreement. A tester is the mechanical gate. I am the taste gate.
- **A rule of life for agents.** A one-page charter the agent reads before touching anything; lessons go back into it when the project closes. A "push discipline" rule exists because an agent once shipped an unreviewed commit.
